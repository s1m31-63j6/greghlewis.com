# Religious Voices — Python LangChain server

This is the production backend for the Religious Voices chatbot. It replaces
the earlier TypeScript / AWS Bedrock implementation with a pure-Python stack:

| Layer        | Library                                  |
| ------------ | ---------------------------------------- |
| Web          | FastAPI + Uvicorn                        |
| Orchestration| LangChain LCEL + `langchain_anthropic`   |
| LLM          | Claude Sonnet 4.5 via the Anthropic SDK  |
| Embeddings   | `BAAI/bge-base-en-v1.5` (sentence-transformers) |
| Vector store | Chroma (persistent, on-disk)             |
| Captcha      | Cloudflare Turnstile (server-side verify)|

## Why this architecture (vs. Bedrock)

This is a deliberate contrast to the NFL chat elsewhere on the site, which
is a TypeScript-first AWS Bedrock RAG:

- **Embeddings run locally.** `BAAI/bge-base-en-v1.5` is a 110M-parameter
  sentence-transformer that retrieves the SOTA passages on MTEB benchmarks
  among free open-weights. Running it locally means we can swap models,
  fine-tune on the corpus, or train one from scratch later — no managed
  service in the loop.
- **Chroma owns retrieval.** A real vector DB instead of a 1024-dim
  Float32Array scan in TypeScript. Metadata filtering (by leader_id) is
  one parameter, not a loop predicate.
- **LangChain LCEL orchestrates.** Composable Runnables for retrieval,
  prompt building, and streaming — the prompt template and chain are
  visible objects you can introspect, not hand-rolled string concatenation.
- **Direct Anthropic SDK for the LLM.** Cuts the Bedrock indirection. The
  cache breakpoints land directly on the wire via `cache_control` on
  system content blocks — verified two-breakpoint caching engaged.

## Run locally

```bash
cd projects/religious-voices

# 1. Install deps (uv-managed)
uv sync

# 2. Set the API key
cat > .env <<EOF
ANTHROPIC_API_KEY=sk-ant-...
# Optional: TURNSTILE_SECRET_KEY=...  (unset in dev → captcha verify skipped)
EOF

# 3. Build the corpus (scrapes ~50 sources, embeds with sentence-transformers,
#    writes to chroma_db/). One-time + whenever sources change.
uv run python build.py

# 4. Start the API server
uv run uvicorn server.main:app --reload --port 8000
```

## Endpoints

- `GET /health` — liveness probe
- `GET /leaders` — returns leaders with chunks in the corpus, sorted by
  era within each tradition. Read by the Next.js frontend at SSR time to
  populate the dropdowns.
- `POST /chat` — SSE stream. Request body:
  ```json
  {
    "query": "What is karma yoga?",
    "leaderId": "vivekananda",
    "history": [],
    "turnstileToken": "..."
  }
  ```
  Stream events:
  - `meta`  — emitted once after retrieval, before LLM tokens
  - `text`  — per-token deltas
  - `done`  — final event with usage stats (incl. cache reads/writes)
  - `error` — only on failure

```
../.env            — local API keys; gitignored
```

## Deploy notes

For an MVP, run on the same box as the Next.js dev server and let the
frontend hit `http://localhost:8000`. For production:

- **Lambda + Mangum** (recommended for low traffic): the sentence-transformer
  weights add ~440 MB; use Lambda layers + 2-3 GB memory.
- **App Runner / ECS Fargate**: standard FastAPI deploy. CORS already
  configured to accept the Amplify origin via
  `RELIGIOUS_VOICES_CORS_ORIGIN` env var.

The Chroma DB committed at `projects/religious-voices/chroma_db/` is
~150 MB. Ship it as part of the deploy bundle or to S3.

## What to call it in interviews

> "It's a Python RAG built with LangChain on top of Chroma. Embeddings
> are local sentence-transformers (`BAAI/bge-base-en-v1.5`, 768-dim).
> The LLM is Claude Sonnet 4.5 via the Anthropic SDK with
> two-breakpoint prompt caching — one breakpoint shares the persona
> template across all leaders, the other caches the per-leader identity
> card so multi-turn sessions hit the cache. The chat surface is a
> Next.js 16 React client that streams via SSE."
